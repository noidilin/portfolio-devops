GCP IAM/Auth Cheatsheet for AWS SSO Users

Best-practice default: human logs in with gcloud auth login, Terraform/app code uses ADC, privileged automation uses service account impersonation, GCE workloads use an attached user-managed service account. Avoid service account keys.

Concept map

AWS IAM policy statementIAM role binding in an allow policyYou grant roles, not raw permissions, to principals on a resource.

Permissions boundaryDeny policy / Principal Access Boundary / Org PolicyNot a one-for-one match. GCP has separate policy types and resource hierarchy controls.
AWS profile / aws-sso sessiongcloud configuration + active account/projectgcloud CLI credentials and ADC credentials are separate stores.

Session inspection commands

# Who will gcloud commands use?
gcloud auth list
gcloud config list account project compute/region compute/zone

# Current access token for gcloud commands
gcloud auth print-access-token

# What ADC will libraries/Terraform usually use?
gcloud auth application-default print-access-token

# Switch account/project/configuration
gcloud config set account YOU@example.com
gcloud config set project PROJECT_ID
gcloud config configurations list
gcloud config configurations activate lab-gce

# One command as a service account, without changing active login
gcloud compute instances list \
  --impersonate-service-account=tf-apply@PROJECT_ID.iam.gserviceaccount.com

Lab 05 migration auth shape

  1. Local human: logs in with gcloud auth login; minimal project roles for learning and impersonation.
  2. Terraform apply identity: user-managed service account, impersonated locally and by CI. This is closest to your GitHub OIDC apply role.
  3. GCE runtime identity: user-managed service account attached to VM. Grant only Artifact Registry read/logging permissions needed by the instance.
  4. CI identity: GitHub Actions should use Workload Identity Federation, not service account keys.

Red flag: downloading a service account JSON key for local Terraform. Prefer impersonation or federation; keys are long-lived bearer secrets.
