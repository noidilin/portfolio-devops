AWS → GCP Auth Lane Map

Core rule: ask “who is calling the API?” If it is gcloud, use the gcloud lane. If it is Terraform/client libraries/local app code, use the ADC lane. If it is code already running on GCP, use the metadata lane.

Minimal command crib

# Manual CLI identity

gcloud auth login
gcloud auth list
gcloud config list account project auth/impersonate_service_account

# One manual command as a deploy service account

gcloud compute instances list \
  --impersonate-service-account=tf-plan@PROJECT_ID.iam.gserviceaccount.com

# Local ADC for Terraform/client libraries, with impersonation

gcloud auth application-default login \
  --impersonate-service-account=tf-plan@PROJECT_ID.iam.gserviceaccount.com

# GCE runtime: no login command; attach SA to VM

gcloud compute instances create VM_NAME \
  --service-account=vm-runtime@PROJECT_ID.iam.gserviceaccount.com \
  --scopes=cloud-platform

Do not flatten the lanes. In AWS, your profile often feels like “the one session.” In GCP, it is normal for active gcloud account, ADC identity, GitHub WIF identity, and GCE metadata identity to all be different.
