GCP Auth Terminology Glossary

Shortcut: gcloud auth login is for the gcloud CLI. gcloud auth application-default login is for Application Default Credentials, used by client libraries and many tools such as Terraform providers.

Core terms

Principal
An authenticated identity that can receive access: user, group, service account, workforce identity, or workload identity. AWS-ish: IAM user/role/federated principal.
User account
A human identity, often a Google Account, Google Workspace / Cloud Identity user, or a federated workforce identity.
Service account
A workload identity managed by Google Cloud. It is both a principal that can access resources and a resource that other principals can be allowed to impersonate or attach.
Role
A bundle of permissions, like roles/compute.instanceAdmin.v1. GCP IAM grants roles, not individual permissions directly.
Allow policy
A policy attached to a resource containing role bindings: “principal X has role Y on resource Z.” Inherited from organization → folder → project → service resource.
gcloud configuration
A named set of CLI properties such as account, project, region, zone, and impersonation settings. AWS-ish: named profile settings, but with separate auth storage.
Active account
The principal gcloud will use by default, unless overridden by flags, environment variables, credential files, or impersonation.
ADC
Application Default Credentials: a lookup strategy used by Google auth libraries to find credentials for code/tools. It is not the same as the active gcloud account.
Quota project
The project charged/used for quota by client libraries when calling APIs with ADC. This can be separate from the resource project.
Access token
Short-lived bearer token sent to Google APIs. You usually inspect it for debugging, not store it as your main auth method.
Service account impersonation
A principal gets short-lived credentials for a service account, if allowed. AWS-ish: closer to STS AssumeRole than to a static access key.
Workforce Identity Federation
Federation for human users from an external IdP. AWS-ish: IAM Identity Center / enterprise SSO area.
Workload Identity Federation
Federation for non-human workloads outside Google Cloud, such as GitHub Actions. AWS-ish: GitHub OIDC role assumption.

Which auth command?

Use caseCommand/patternWhy
You type gcloud compute instances listgcloud auth loginAuthorizes the gcloud CLI to act as your user.
You run Terraform Google provider locallygcloud auth application-default login or ADC impersonationTerraform commonly uses ADC, not the gcloud active account.
You run local app code using Google client librariesgcloud auth application-default loginClient libraries search ADC automatically.
You want one CLI command as a deploy service accountgcloud ... --impersonate-service-account=SATemporary per-command elevation without switching login.
Code runs on GCE VMAttach a service account to the VMADC gets tokens from metadata server. No local login or key.
GitHub Actions deploys to GCPWorkload Identity FederationShort-lived federated tokens. No JSON key in secrets.

Inspection commands

gcloud auth list

gcloud config configurations list
gcloud config list account project compute/region compute/zone auth/impersonate_service_account

gcloud auth print-access-token

gcloud auth application-default print-access-token
